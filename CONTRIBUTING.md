## Использование ИИ

Использование ИИ в нашем проекте не запрещается, однако помните, что вы несёте полную ответственность за результат вне зависимости от способа его получения.

## Настройка среды для проекта

На наш взгляд, наиболее удобной средой для работы над проектом является [Visual Studio Code](https://code.visualstudio.com) с плагином [LaTeX Workshop](https://marketplace.visualstudio.com/items?itemName=James-Yu.latex-workshop).

Чтобы LaTeX Workshop корректно работал с конспектами в нашем проекте, установите следующий параметр:
```
"latex-workshop.latex.rootFile.indicator": "\\begin{document}"
```
Это позволит корректно находить главный файл в проекте и пересобирать PDF по мере внесения изменений в любой файл соответствующего конспекта.

Помимо редактора и соответствующего плагина, вам потребуется и сам компилятор LaTeX'а. Дальнейшие инструкции зависят от используемой вами операционной системы.

На Windows мы рекомендуем использовать [WSL](https://learn.microsoft.com/en-us/windows/wsl/install), поскольку с ним гораздо проще установить все необходимые программы.

Для Linux необходимо установить следующие пакеты (пример приведён для Ubuntu и Debian, для других дистрибутивов следует узнать имена соответствующих пакетов):
```shell
sudo apt install -y texlive texlive-latex-extra texlive-lang-cyrillic
```

Если вы работаете на macOS, то, скорее всего, наиболее удобным способом для вас будет установка с помощью [Homebrew](https://brew.sh):
```shell
brew install texlive
```

## Настройка SSH-ключей

Для дальнейшей работы рекомендуем настроить подключение по SSH. Об этом можно прочитать в официальной [документации GitHub](https://docs.github.com/en/authentication/connecting-to-github-with-ssh).

## Начало работы с репозиторием

Склонируйте репозиторий на ваш компьютер. Если работаете под Windows, то это удобнее сделать сразу в WSL.
```shell
git clone git@github.com:lectoriy-rt/lectoriy-rt.git
```

После этого нужно переключить ветку на `staging`:
```
git checkout staging
```

## Структура проекта

У каждого конспекта есть соответствующий каталог, в котором лежит всё необходимое для его сборки. Это позволяет максимально адаптировать шаблон под нужды конкретного курса.

Пути к каталогам должны придерживаться следующего формата:
```
{Lectures,Seminars,Exams,Extra,Samples}/Semester_[1-12]/<Subject>/<year>_<Lecturer_Name>
```
Здесь `{` и `}` обозначают выбор из заданного множества, `[` и `]` — любое число из диапазона, `<` и `>` — произвольную строку определённого типа.

Например, каталог курса математического анализа Знаменской Л.Н. для первокурсников осеннего семестра 2026 года будет иметь следующий путь:
```
Lectures/Semester_1/Mathematical_Analysis/2026_Znamenskaya_L_N
```

Структура каждого отдельного конспекта выглядит следующим образом:
```
.
├── Images
│   └── lectoriy-rt-logo.pdf
│   └── ...
├── Lectures
│   ├── lecture1.tex
│   └── ...
├── main.tex
├── preamble.tex
├── tableofcontents.tex
└── titlepage.tex
```

В файле `preamble.tex` находится преамбула: подключения необходимых пакетов и определения команд. Файл `titlepage.tex` отвечает за титульную страницу, `tableofcontents.tex` — за оглавление и, наконец, `main.tex` является главным файлом, в котором включаются все остальные. Его содержимое выглядит следующим образом:
```
\input{preamble}

\begin{document}
\input{titlepage}
\input{tableofcontents}
\input{Lectures/lecture1}
...
\end{document}
```

## Добавление нового курса

Для добавления нового курса скопируйте каталог `Template` по нужному вам пути. После чего **сразу** добавьте логотип в индекс репозитория:
```shell
git add -f Images/lectoriy-rt-logo.pdf
```
Ведь при добавлении файлов обычной командой `git add` он будет проигнорирован, поскольку `.gitignore` содержит правило для PDF-файлов.

## Сборка

Для получения PDF-файла любого курса нужно открыть в VS Code соответствующий `main.tex` и нажать на стрелку справа сверху в панели редактора. Открывать главный файл для сборки нужно лишь единожды: далее можно редактировать любой файл в проекте и PDF будет пересобираться автоматически.

## Стиль кода

Основная цель используемых нами правил — получить исходный текст, который можно удобно читать, не собирая PDF. Для этого мы придерживаемся следующих правил:

- не более 100 символов в одной строке;

- размер отступа — 4 пробела;

- окружения по умолчанию не выделяются отступом, исключения составляют окружения для графики или математических формул, отображаемых по центру страницы (`\[` и `\]`, `align`, `gather` и т.п.);

- продолжение строки выделяется отступом только если она выходит в список (окружения `itemize`, `enumerate` и т.п.) или является частью одной отображаемой строки в получаемом PDF-файле (это верно, например, для математических формул);

- вместо `$ $` и `$$ $$` мы используем `\(`, `\)` и `\[`, `\]`, поскольку этот способ окружения формул является более современным для LaTeX, а также выдаёт более точную диагностику при пропуске какого-либо из символов.

## Полезное

Чтобы быстро избавиться от всех лишних файлов в репозитории, можно дать команду:
```shell
git clean -fdX
```
